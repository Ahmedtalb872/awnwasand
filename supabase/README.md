# ربط حسابات الطلاب ورفع الملفات عبر الإنترنت

GitHub Pages يستضيف واجهة Flutter فقط. لتفعيل الحسابات والملفات المشتركة بين الأجهزة:

1. أنشئ مشروع Supabase وشغّل `schema.sql` مرة واحدة في SQL Editor في مشروع جديد. ينشئ الجداول وسياسات RLS وحاوية ملفات خاصة بحد 50 ميجابايت.
2. من Authentication → URL Configuration أضف رابط الموقع `https://ahmedtalb872.github.io/awnwasand/` إلى Site URL وRedirect URLs.
3. سجّل حسابك من التطبيق بعد ربطه، وأكّد بريدك. رقّ حساب المشرف من SQL Editor باستخدام UUID حسابك كما في نهاية `schema.sql`. لا يستطيع العميل تغيير الدور.
4. أضف في إعدادات المستودع → Secrets and variables → Actions → Variables متغيري `SUPABASE_URL` و`SUPABASE_ANON_KEY` (المفتاح العام anon / Publishable فقط). أعد تشغيل مهمة Publish Flutter web preview. بدون المتغيرين تبقى المعاينة تجريبية محلية.

التشغيل المحلي:

```bash
flutter run --dart-define=SUPABASE_URL=https://your-project.supabase.co --dart-define=SUPABASE_ANON_KEY=your-public-key
```

لا تضع مفتاح service_role في التطبيق أو المستودع. الصلاحيات الفعلية تحميها قاعدة البيانات والتخزين، وليس إخفاء أزرار الإدارة. الطالب يقرأ ملفه، وينضم للدورات المنشورة، ويقرأ ملفات الدورات التي انضم إليها عبر روابط مؤقتة. المشرف وحده يضيف الدورات ويرفع موادها ويطّلع على ملفات الطلاب.

نسخة العرض دون إعدادات سحابية تستخدم SharedPreferences لبيانات الطلاب والدورات، وIndexedDB لملفات المتصفح، ومجلد التطبيق لملفات الهاتف. هذه نسخة تجريبية على الجهاز؛ ليست تسجيل دخول آمنًا أو مشاركة للملفات عبر الإنترنت. تم فصل تقدم المسارات الأساسي حسب معرّف كل طالب، لكنه يبقى محليًا حتى في النسخة المتصلة. تقدم مواد الدورات يحفظ في Supabase عند الاتصال.

شغّل المخطط في مشروع جديد قبل اعتماده، واختبر الدخول بحساب مشرف وحسابَي طالب للتأكد من عزل الملفات ومنع تغيير الأدوار. لم يُطبَّق المخطط على خدمة فعلية أثناء إنشاء التغيير لعدم توفر مشروع Supabase. الشهادات والإنجازات داخل التطبيق سجلات تعلم شخصية.
